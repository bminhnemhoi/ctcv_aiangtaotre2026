# E12 — Triển khai (staging → production, giám sát, backup, failover) + PWA offline

## Mục tiêu
URL công khai sống liên tục từ ngày nộp đến chung kết (CF-07): tầng luôn bật (VPS CPU: web/API/Postgres/Qdrant + `planner_small` Qwen3.5-2B GGUF qua llama.cpp + PhoWhisper-tiny + TTS cache) và tầng GPU bật theo lịch làm "fast path", tự fallback theo health check; máy dự phòng cùng image, chuyển DNS ≤ 5 phút; PWA offline cho lớp mất mạng (thay APK — F09/ADR-006). Bản E12-lite (Pha A): staging HTTPS + status page từ 21–22/9 (tiên quyết E04 — N03).

## Đầu vào
- `docs/idea.md` §10 (triển khai, 48 giờ ổn định, chi phí, bản offline) + Errata; `docs/plan.md` §8 (môi trường, quy trình deploy, giám sát, backup, đóng băng, sự cố), §6 hàng E12; `docs/prompt.md` §5 D4.
- `docs/decisions/E01-brief.md` D14 (Dockerfile ở `deploy/docker/`), D29 (profiles `cpu`/`gpu`; `VLLM_BASE_URL` trỏ máy GPU qua SSH tunnel/Tailscale; llama.cpp là đường CPU chính thức; `make doctor GPU=1`), D30 (APK → PWA offline), §10 (`deploy ENV=`, `rollback TAG=`, `failover`, `backup`, `restore-drill`), §17.10 (`models` image vLLM upstream; Cloudflare DNS-only nếu cam kết "trong nước"; staging HTTPS là tiên quyết E04).
- ADR-006 (lịch, tag v1.0/v1.5/v2.0), ADR-005 (retention, in-country hosting); phát hiện F09 (PWA offline = service worker cache kịch bản JSON + câu huấn luyện viên sinh sẵn + clip TTS; hỏi đáp/kèm cặp hiện "cần mạng"), F11, S7, S13, N16 (domain `.vn` lead time → subdomain sẵn có), ETH-12 (GPU cloud trong nước nếu được, nếu không ghi trung thực).
- Kết quả E01 (Compose, CI `release.yml`), E04/E05 (dịch vụ chạy), E11 (status page, load test).

## Công việc
1. E12-lite (Pha A, 21–22/9): `make deploy ENV=staging` — `deploy/docker-compose.prod.yml` + `deploy/caddy/Caddyfile` (HTTPS tự động) trên máy GPU thuê, hoặc `cloudflared` tunnel tạm nếu domain chưa có; `deploy/status/` Uptime Kuma; `.github/workflows/release.yml` deploy khi tag `v*`; `docs/ops/RUNBOOK.md` mục staging.
2. `deploy/docker-compose.yml` profiles: `cpu` (máy dev Windows, CI, VPS luôn bật: `models` = llama.cpp server với `Qwen3.5-2B` GGUF) và `gpu` (vLLM image upstream, `--limit-mm-per-prompt image=1`, `--max-model-len 4096`, multi-LoRA nếu D9 chốt); `services/agent` chọn `planner` hay `planner_small` theo health của endpoint (fallback tự động, ghi chế độ lên status page — CF-07).
3. `deploy/scripts/*.sh` (`deploy.sh`, `rollback.sh`, `failover.sh`, `backup.sh`, `restore_drill.sh`, `smoke.sh`): build image có hash → `make check` → đẩy registry riêng → SSH → `docker compose pull && up -d` + Alembic → smoke test 12 kịch bản qua API (6 ở bản lite) → cập nhật status → Telegram; `make rollback TAG=` ≤ 2 phút; `make failover` chuyển DNS sang máy dự phòng ≤ 5 phút.
4. `make backup`: PostgreSQL dump mỗi 6 giờ + Qdrant snapshot hằng ngày lên object storage khác máy, giữ 14 bản (ADR-005); ảnh màn hình không backup; `make restore-drill` diễn tập trước T-72h (không hằng tuần — F13).
5. `apps/web/` PWA offline: service worker cache toàn bộ `sandbox/scenarios/*.json` đã ship, `coach_line`/`hint` sinh sẵn theo (scenario, screen, mistake), clip TTS sinh sẵn; hỏi đáp/kèm cặp/drill TTS hiện "cần mạng"; test tắt mạng chơi 6 kịch bản.
6. `apps/android/README.md`: chỉ ghi "hướng phát triển: APK offline (Qwen3.5-2B GGUF + PhoWhisper-tiny)"; không build APK ở v1.0/v2.0.
7. Production (Pha D): VPS CPU trong nước (FPT/Viettel/VNG/VNPT nếu có — ETH-12) + máy GPU theo lịch + máy dự phòng; Cloudflare DNS-only; `make doctor GPU=1` kiểm SSH/`nvidia-smi`/vLLM; ngân sách GPU: Pha A 60–80 giờ phục vụ, giữ phần còn lại của 300 giờ cho Pha D + 18–22/11 (S7, CF-07).
8. Đóng băng: quy trình T-72h/T-60h/T-48h theo `docs/ops/RUNBOOK.md`; `docs/ops/incidents.md` ghi sự cố; trực ca 3 người.

## Đầu ra
Staging HTTPS + status page (Pha A); production 2 tầng + máy dự phòng + backup + failover diễn tập (Pha D); PWA offline chơi 6 kịch bản khi tắt mạng; `docs/ops/RUNBOOK.md` đủ lệnh; export Uptime Kuma làm minh chứng uptime.

## Test nghiệm thu (tự động, phải xanh)
- `make build` — mọi image build từ `deploy/docker/*.Dockerfile`, tổng < 8 GB không tính model (plan §3); `models` không build (pull image vLLM upstream).
- `make deploy ENV=staging` từ CI khi tag → `deploy/scripts/smoke.sh` 6/12 kịch bản qua API xanh; `make rollback TAG=<trước>` hoàn tất ≤ 2 phút (đo trong log).
- `make failover` — diễn tập chuyển máy dự phòng ≤ 5 phút, `/health` xanh sau chuyển (plan §8; prompt.md D4).
- `make restore-drill` — khôi phục dump mới nhất vào Postgres tạm, số dòng `sessions` khớp.
- `E2E=1 make e2e` — ca "offline": tắt mạng (Playwright `context.setOffline(true)`) → 6 kịch bản chơi được; hỏi đáp hiện "cần mạng" (thay tiêu chí "APK chạy 6 kịch bản khi tắt mạng" của plan §6).
- Uptime Kuma: xanh 24 giờ liên tục trên staging trước prod và ≥ 24 giờ trước ngày nộp (plan §6, §15); uptime ≥ 99 % trong 48 giờ đóng băng (DoD #6).
- `make doctor GPU=1` — SSH, `nvidia-smi`, vLLM `/v1/models` trả `Qwen/Qwen3.5-9B`.

## Không được làm
Build APK Android (BACKLOG); tắt tầng CPU luôn bật sau ngày nộp; deploy ngoài CI/tag trong thời gian đóng băng; bật Cloudflare proxy nếu hồ sơ cam kết "máy chủ trong nước" (hoặc sửa câu cam kết — ETH-12); backup ảnh màn hình; lưu secret ngoài `.env`/GitHub Secrets; `docker system prune` (guard chặn); vượt ngân sách GPU mà không hỏi.

## Câu hỏi mở (≤ 3)
1. Nhà cung cấp GPU/VPS: trong nước (giữ cam kết "máy chủ trong nước") hay RunPod/Vast (rẻ, có ngay) + sửa câu cam kết trong hồ sơ?
2. Domain: mua `.vn` (1–3 ngày, giấy tờ) hay dùng subdomain sẵn có cho bản nộp?
3. Máy dự phòng: thuê từ Pha D (chi phí) hay chỉ trong tuần chung kết?

## Checklist cho người dùng (≤ 30 phút)
- [ ] Mở URL staging trên 4G và Wi-Fi; status page hiện chế độ GPU/CPU đúng thực tế.
- [ ] Tắt mạng điện thoại, mở PWA đã cài: chơi 2 kịch bản; bật lại mạng, hỏi 1 câu.
- [ ] Xem log `make failover` diễn tập (thời gian < 5 phút) và export Uptime Kuma 24 giờ.
- [ ] Xác nhận hóa đơn/giờ GPU đã dùng khớp `docs/status/DAILY.md` (chi phí lũy kế).
