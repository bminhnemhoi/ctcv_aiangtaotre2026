# E06 — Pipeline dữ liệu tổng hợp (36 file kịch bản, hội thoại SFT/DPO, LLM-judge)

## Mục tiêu
`make data` chạy trọn: sinh đủ 12 kịch bản × 3 mức = 36 file `sandbox/scenarios/<slug>-l<level>.json` từ kho hướng dẫn + 4 kịch bản few-shot của E02 (C11), sinh ≥ 8.000 hội thoại SFT + 2.000 cặp DPO qua bộ lọc ràng buộc và LLM-judge ≥ 4/5, báo cáo HTML 30 mẫu để người dùng duyệt; mọi tập có registry, sha256, giấy phép và nguồn sinh (LIC-09).

## Đầu vào
- `docs/idea.md` §6 (lộ trình fine-tune bước 1–2), §7 (bảng dữ liệu, kiểm định, giấy phép CC BY 4.0 cho dữ liệu tổng hợp); `docs/plan.md` §6 hàng E06, §7 `make data` (các bước `synth_scenarios`, `synth_dialogues`, `filter_judge`, `build_eval_sets` của `python -m ctcv_data.pipeline`; tên và thứ tự bước theo `data/README.md`).
- `docs/decisions/E01-brief.md` §5 (12 id kịch bản cố định), §8 (`config/prompts/judge.v1.md`, model `judge`), §9 + §17.4 (registry: `generator_model`, `generator_license`, `tos_url`, `tos_checked_on`), D21/D20 (`docs/prompt-log/tools/` lưu prompt template của bước sinh/judge — N14).
- Phát hiện C11 (E06 sinh 36 file; E10 dựng UI), LIC-09 (không dùng API thương mại có ToS cấm huấn luyện model cạnh tranh; ưu tiên model mở tự host / self-instruct bằng Qwen3.5-9B base), N05 (E06 không phụ thuộc E05 — chỉ cần kịch bản E02, prompt coach, guardrails E01), F13 (tập eval cắt: 200 hội thoại).
- Kết quả E01 (`config/prompts/coach.v1.md`, `judge.v1.md`, guardrails, registry schema), E02 (4 kịch bản mức 1, validator), E03 (kho hướng dẫn cho bước sinh kịch bản).

## Công việc
1. `data/src/ctcv_data/pipeline/synth_scenarios.py` (bước `synth_scenarios`; stub "CHƯA HIỆN THỰC" đã có — hiện thực tại chỗ, không tạo `scenarios.py`): LLM đọc hướng dẫn trong `data/clean/guides/` + 4 few-shot → máy trạng thái JSON theo `config/schemas/scenario.schema.json`; 12 id cố định của brief §5, mức 1–3 (`<slug>-l<level>`); 100 % qua `ctcv_sandbox.validator`; báo cáo 30 mẫu duyệt tay.
2. `data/src/ctcv_data/pipeline/synth_dialogues.py` (bước `synth_dialogues`; 5 persona khai báo ngay trong module, không tách `personas.py`/`synth.py`): 5 persona (giọng miền, nhầm lẫn, lo lắng, vội, mắt kém) × 12 kịch bản × lỗi thường gặp → hội thoại huấn luyện viên mẫu; ràng buộc cứng mỗi lượt ≤ 2 câu, kết thúc bằng hành động, xác nhận ý định lượt đầu; cặp DPO "đúng phong cách" vs "trả lời dài kiểu chatbot".
3. `data/src/ctcv_data/pipeline/filter_judge.py` (bước `filter_judge`, một module cho cả hai việc): lọc ràng buộc chạy trước — loại hội thoại vi phạm (`ctcv_agent.guardrails.enforce_style`), chứa `banned_terms`, câu > 25 từ, yêu cầu thông tin nhạy cảm, dữ kiện không có trong kho; LLM-judge 1–5 chạy sau với `config/prompts/judge.v1.md`, giữ ≥ 4.
4. Model sinh/judge: mặc định `config/models.yaml: judge` (Qwen3.5-9B tự host trên máy GPU thuê, Apache-2.0 — không vướng ToS); nếu dùng `SYNTH_LLM_PROVIDER` thương mại thì đọc ToS ngày hiện tại, lưu bản chụp vào Drive, kê khai trong `datasets.yaml` (`generator_model`, `generator_license`, `tos_url`, `tos_checked_on`) — LIC-09; ngân sách API ≤ `training/budget.json: api_vnd_limit` (hook `budget.py` chặn).
5. Báo cáo duyệt mẫu do `filter_judge.py` xuất (không thêm module `report.py`): HTML `eval/reports/<ngày>-data-review.html` với 30 mẫu gắn cờ ngẫu nhiên/điểm thấp, nút duyệt/sửa; kết quả duyệt ghi lại vào `eval/reports/`.
6. `docs/prompt-log/tools/`: lưu prompt template + tham số + 3 mẫu đầu ra của bước synth/judge (N14; không cần 8.000 bản).
7. `data/registry/datasets.yaml`: `scenarios-v1` (36 file, `source: synthetic`, CC BY 4.0), `coach-sft-v1`, `coach-dpo-v1` với sha256, `size`, `used_for`, `pii: none`, `redistribute: true`.
8. `data/src/ctcv_data/pipeline/build_eval_sets.py` (bước `build_eval_sets`, stub đã có) — tập eval seed cố định (cắt theo F13): 200 hội thoại giữ lại, 300 Q&A, 100 red-team (mở rộng 200 trước chung kết) → `eval/sets/` (gitignore; manifest trong `eval/sets/samples/`).

## Đầu ra
36 file kịch bản qua validator (E10 dựng UI cho 8 luồng còn lại); `data/sft/train.jsonl` ≥ 8.000, `data/dpo/pairs.jsonl` ≥ 2.000 (gitignore, sha256 trong registry); báo cáo duyệt HTML; registry đầy đủ trường LIC-08/09/10; `docs/prompt-log/tools/` có prompt sinh dữ liệu; README `data/` mục "make data".

## Test nghiệm thu (tự động, phải xanh)
- `uv run pytest data` — filter loại đúng hội thoại vi phạm (fixture); judge parse điểm 1–5; `synth_scenarios.py` chỉ ghi file qua validator; registry ghi sha256 khớp file.
- `make data` — 36/36 file qua `ctcv_sandbox.validator`; ≥ 8.000 SFT + 2.000 DPO qua lọc (plan §6); báo cáo HTML 30 mẫu sinh ra; ≤ 5 % mẫu bị người dùng từ chối trong 30 mẫu (ghi kết quả duyệt vào `eval/reports/`).
- `uv run pytest tests/config` — `datasets.yaml` qua schema; mọi mục `synthetic` có `generator_model` + `generator_license`; không mục nào `license: unknown`.
- `uv run pytest sandbox` — 36 file nạp được vào engine, mỗi file đi trọn ít nhất một đường thành công.
- `make check QUICK=1` xanh (bước sinh dữ liệu không chạy trong `check`).

## Không được làm
Dùng API thương mại có ToS cấm dùng đầu ra để huấn luyện (LIC-09) mà không kê khai; vượt 500.000 đ API hay 20 giờ GPU mà không hỏi; commit `data/sft`, `data/dpo`, `data/clean`; sinh kịch bản có nhãn hiệu thật; bỏ bước duyệt 30 mẫu; sửa `config/eval.yaml` để cho xanh; ghi hội thoại có PII (validator + regex chặn).

## Câu hỏi mở (≤ 3)
1. Model sinh dữ liệu: tự host Qwen3.5-9B (chậm, ~0 đ, không vướng ToS) hay thuê API model mở qua nhà cung cấp cho phép dùng output (nhanh, ≤ 500.000 đ)?
2. Có sinh mức 2–3 cho cả 12 kịch bản ngay (36 file) hay chỉ mức 1 cho 8 kịch bản mới + mức 2–3 cho 4 kịch bản cũ trước, phần còn lại sau pilot?

- [ ] Đọc 3 kịch bản sinh tự động mức 3 (ví dụ `khai-sinh-truc-tuyen-l3`): thứ tự màn hình có giống app thật không?
- [ ] Xác nhận nhà cung cấp/model sinh dữ liệu trong `data/registry/datasets.yaml` đúng với thực tế đã dùng (kê khai trung thực).
